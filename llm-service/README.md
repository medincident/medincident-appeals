# llm-service

FastAPI-обёртка над Ollama, которая запускает Qwen2.5-3B (или любую другую совместимую модель) и отдаёт тот же контракт API, что и `nlp-service`. Это **подход 1** — целиком решает задачу анализа обращения пациента одним вызовом к LLM.

## Зачем это нужно

В проекте две независимые реализации одного контракта `POST /analyze`:

| | `llm-service` | `nlp-service` |
|--|---------------|----------------|
| Подход | Один вызов к LLM | 3 специализированные модели |
| Размер | ~1.9 GB (Qwen2.5-3B Q4_K_M) | ~370 MB |
| Время на запрос (CPU) | ~130s | ~1s |
| Качество без обучения | Лучше | Среднее |
| Новые категории | Подаём в промпт | Эмбеддинг считается на лету |

`llm-service` нужен чтобы:

- быстро получить рабочую систему без fine-tune'а специализированных моделей;
- иметь baseline для сравнения качества с NLP-пайплайном;
- сохранить совместимость с кодом, который ходит в OpenAI-совместимый API (`/v1/chat/completions`) — например, `benchmark_llm.py`.

## Что делает сервис

1. Запускает `ollama serve` как subprocess (слушает `127.0.0.1:11435` внутри контейнера).
2. Ждёт готовности Ollama, докачивает модель если её нет в volume.
3. Подключается к NATS JetStream KV, читает категории и подписывается на изменения.
4. Поднимает FastAPI на `:11434` со следующими эндпоинтами.

## API

| Метод | Путь | Описание |
|-------|------|----------|
| POST | `/analyze` | Полный пайплайн: text → структурированный JSON. Контракт совпадает с `nlp-service`. |
| GET | `/health` | Статус Ollama + NATS + размер кэша категорий. |
| GET | `/categories` | Текущий снапшот категорий из NATS. |
| GET | `/` | Просто `Ollama is running` — для health-check старых клиентов. |
| ALL | `/v1/*`, `/api/*` | Прозрачный прокси в Ollama (OpenAI-совместимый API). |

### `POST /analyze`

```json
// request
{"text": "пациент упал с кровати ночью"}

// response
{
  "is_important": true,
  "reason": "Содержит жалобу на падения пациентов в МО",
  "formalized_text": "Пациент упал с кровати в ночное время...",
  "theses": ["Падение с кровати ночью"],
  "category": {"id": "cat_1", "name": "Организация ухода"},
  "subcategory": {"id": "sub_1_1", "name": "Падения пациентов в МО"}
}
```

Если LLM вернул не-JSON, сервис возвращает безопасный fallback с `is_important=true` (false negative в медицине дороже false positive).

## Конфигурация

Переменные окружения:

| | По умолчанию | Описание |
|--|-------------|----------|
| `OLLAMA_MODEL` | `qwen2.5:3b` | Модель для `ollama pull` |
| `NATS_URL` | `nats://nats:4222` | Адрес NATS |
| `HTTP_PORT` | `11434` | Порт FastAPI |

## Запуск через docker compose

```bash
docker compose --profile llm up llm-service
```

Порт 11434 не пробрасывается наружу — сервис доступен только внутри Docker-сети по имени `llm-service:11434`. Для доступа с хоста используй `test_llm.py` — он определяет IP контейнера через `docker inspect`.

## Бенчмарк / тесты

```bash
python3 test_llm.py                   # 1 пример
python3 test_llm.py --n 5             # 5 примеров + summary
python3 benchmark_llm.py --limit 30   # 30 примеров
```

`benchmark_llm.py` ходит в `/v1/chat/completions` через прокси-ручку — то есть напрямую к Ollama, без нашей `/analyze` обёртки.
