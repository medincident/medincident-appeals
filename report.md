## 1. Датасет

### 1.1 Назначение и формат

Датасет `dataset.jsonl` используется для обучения и оценки двух подходов к обработке обращений пациентов:

- **Подход 1 (LLM)** — fine-tune Qwen2.5-3B, датасет задаёт формат ответа (JSON);
- **Подход 2 (NLP-pipeline)** — fine-tune rubert-tiny2 (классификатор важности) и rut5-base-multitask (формализация текста и извлечение тезисов).

**Формат каждой строки** (JSONL, chat fine-tune):

```json
{
  "messages": [
    {"role": "user", "content": "текст обращения пациента"},
    {"role": "assistant", "content": "{\"is_important\": true, \"reason\": \"...\", \"formalized_text\": \"...\", \"theses\": [...], \"category\": {...}, \"subcategory\": {...}}"}
  ],
  "template_id": "imp_42"
}
```

Поля ответа модели:

| Поле | Тип | Описание |
|------|-----|----------|
| `is_important` | bool | Является ли обращение медицинским инцидентом |
| `reason` | string | Обоснование классификации |
| `formalized_text` | string | Формализованный медицинский текст (для важных) или исходный текст (для неважных) |
| `theses` | string[] | Ключевые тезисы инцидента (пустой массив для неважных) |
| `category` | object/null | Категория инцидента (`id`, `name`) |
| `subcategory` | object/null | Подкатегория инцидента (`id`, `name`) |

Системный промпт и список категорий **не входят** в датасет — они добавляются динамически при обучении и инференсе. Это позволяет менять набор категорий без перегенерации датасета.

### 1.2 Генерация: скрипт generate_dataset.py

Датасет полностью синтетический — сгенерирован скриптом `generate_dataset.py` с фиксированным seed (`random.seed(42)`) для воспроизводимости.

**Входные данные скрипта:**
- `IMPORTANT_TEMPLATES` — 164 шаблона жалоб, распределённых по 7 категориям и 22 подкатегориям медицинских инцидентов;
- `NOT_IMPORTANT_TEMPLATES` — 35 шаблонов необращений (благодарности, вопросы, тестовые сообщения, ложные тревоги);
- `PREAMBLES` — 15 вариантов вступления ("Здравствуйте!", "Хочу пожаловаться.", "");
- `SUFFIXES` — 15 вариантов завершения ("Прошу принять меры.", "Это очень беспокоит.", "");
- `SYNONYMS` — словарь из 17 слов с синонимами для замен в ядре жалобы;
- `COLLOQUIAL_INSERTS` — 10 разговорных вставок ("ну", "короче", "блин");
- `STYLE_WRAPPERS` — 8 стилевых обёрток ("Я в шоке!", "СРОЧНО!", "Довожу до вашего сведения:");
- `TYPO_REPLACEMENTS` — 28 паттернов опечаток (фонетические ошибки, пропуск букв, слипшиеся слова).

**Алгоритм генерации:**
1. Для каждого шаблона создаётся пул вариаций через комбинации преамбулы, суффикса и аугментаций;
2. Из пула важных случайно отбирается 2250 примеров (75%);
3. Из пула неважных — 750 примеров (25%);
4. Перед добавлением проверяется уникальность текста обращения (дедупликация через `seen_texts: set`);
5. Итоговый список перемешивается (`random.shuffle`).

### 1.3 Шаблоны жалоб

Каждый шаблон — это кортеж из 8 элементов:

```python
(complaint_core,        # ядро жалобы (текст от лица пациента)
 formalized_text,       # формализованная версия (медицинский стиль)
 theses,                # список ключевых тезисов
 cat_id, cat_name,      # категория инцидента
 sub_id, sub_name,      # подкатегория
 reason)                # обоснование важности
```

**Примеры шаблонов:**

Важный (sub_1_1 — падения):
```
Ядро:          "упал с кровати ночью, ударился головой, никто не пришёл когда
                позвал на помощь"
Формализация:  "Пациент сообщает о падении с кровати в ночное время с травмой
                головы. Вызов персонала остался без ответа."
Тезисы:        ["Падение с кровати в ночное время", "Травма головы",
                "Персонал не откликнулся на вызов"]
```

Неважный (ложная тревога):
```
Ядро:          "мне делали укол было больно но врач предупреждал что так бывает
                всё нормально"
Формализация:  "Болезненность при инъекции, о которой пациент был предупреждён
                заранее. Жалоб нет."
Тезисы:        []
```

**Типы шаблонов по содержанию:**

| Тип | Кол-во | Описание |
|-----|--------|----------|
| Стандартные важные | 150 | Жалобы на конкретные инциденты по 22 подкатегориям |
| Длинные важные (200-414 символов) | 5 | Детальные описания с датами, именами, хронологией |
| Короткие важные (4-23 символа) | 5 | Телеграфные жалобы: "упал, больно, помогите" |
| Мультижалобы | 4 | 2+ проблемы в одном обращении |
| Неважные: ложные тревоги | 8 | Медицинские слова, но не инцидент |
| Неважные: отзывы | 4 | Благодарности и комплименты |
| Неважные: вопросы | 13 | Организационные и бытовые вопросы |
| Неважные: тестовые | 6 | "тест", "привет", проверки приложения |

### 1.4 Аугментация: механизмы вариативности

Для каждого шаблона функция `vary()` создаёт вариации через комбинацию нескольких механизмов:

**1. Преамбулы и суффиксы** (комбинаторные, 15 x 15 = 225 комбинаций):
```
""                       + ядро + ""
"Здравствуйте! "         + ядро + " Прошу принять меры."
"Хочу пожаловаться. "    + ядро + " Это очень беспокоит."
"Срочно хочу сообщить: " + ядро + " Когда это исправят?"
...
```

**2. Синонимические замены** (вероятность 30% на каждое слово, применяются к каждой 3-й вариации):

| Исходное слово | Возможные замены |
|----------------|-----------------|
| упал | свалился, грохнулся, рухнул, повалился |
| медсестра | медицинская сестра, сестра, сестричка |
| врач | доктор, лечащий врач |
| больно | болит сильно, невыносимая боль, очень больно |
| еда | пища, питание, кормёжка |
| грубо | по-хамски, нагрубила, грубо и невежливо |
| никто не пришёл | персонал не отреагировал, никто не подошёл |
| ... | (17 слов с синонимами всего) |

**3. Разговорные вставки** (вероятность 20%, применяются к каждой 4-й вариации):
```
"ну упал с кровати ночью..."
"короче медсестра нагрубила..."
"блин таблетку не ту дали..."
```

**4. Стилевые обёртки** (вероятность 15%, применяются к каждой 6-й вариации):
```
"Я в шоке! упал с кровати ночью... Это просто ужас!"
"СРОЧНО! медсестра дала не ту таблетку!!!"
"Довожу до вашего сведения: в палате антисанитария"
"Пишу уже третий раз: никто не реагирует... Когда будет реакция?"
```

**5. Опечатки** (вероятность 30% на каждый паттерн, применяются к каждой 5-й вариации):

| Тип | Примеры |
|-----|---------|
| Фонетические | "что" -> "чта", "потому" -> "патому", "помогите" -> "помагите" |
| Пропуск букв | "которая" -> "котрая", "после" -> "посл" |
| Слипшиеся слова | "не дали" -> "недали", "не могу" -> "немогу" |

В итоговом датасете: ~76 примеров с синонимами, ~148 с разговорными вставками, ~43 со стилевыми обёртками, ~68 с опечатками.

### 1.7 Поле template_id и стратегия split

Каждый пример содержит поле `template_id`:
- `imp_0` ... `imp_163` — для важных шаблонов (164 ID);
- `ni_0` ... `ni_34` — для неважных шаблонов (35 ID).

**Зачем это нужно:** все вариации одного шаблона имеют одинаковое ядро жалобы и отличаются только преамбулой, суффиксом и аугментациями. Если делать случайный train/val/test split по примерам, вариации одного шаблона попадут в разные сплиты — это **data leakage** (утечка данных), завышающая метрики.

**Правильная стратегия split** — разделение по `template_id`:
- Все вариации одного шаблона попадают целиком в один сплит;
- Рекомендуемое соотношение: 70% train / 15% val / 15% test;
- Stratified split: сохранение пропорций категорий в каждом сплите.

## 2. Train/Val/Test Split

### 2.1 Проблема: data leakage при случайном split

При случайном разделении датасета на train/val/test по примерам вариации одного шаблона попадают в разные сплиты. Модель в train видит "упал с кровати ночью... Прошу принять меры", а в val оценивается на "упал с кровати ночью... Это недопустимо" — почти идентичный текст. Метрики завышаются, реальная способность к обобщению не оценивается.

### 2.2 Решение: split по template_id

Каждый пример в `dataset.jsonl` содержит поле `template_id` — идентификатор шаблона, из которого он сгенерирован. Все вариации одного шаблона имеют одинаковый `template_id`.

**Алгоритм split:**
1. Собрать множество уникальных `template_id` (199 шт.);
2. Перемешать шаблоны (`numpy.random.default_rng(42)`);
3. Назначить 70% шаблонов в train, 15% в val, 15% в test;
4. Все вариации каждого шаблона попадают целиком в один сплит.

### 2.3 Результаты split

**Classifier (все примеры, 3000):**

| Split | Примеров | Шаблонов | Important | Not-important |
|-------|----------|----------|-----------|---------------|
| Train | 2133 | 141 | 1573 (74%) | 560 (26%) |
| Val | 420 | 29 | 355 (85%) | 65 (15%) |
| Test | 447 | 29 | 322 (72%) | 125 (28%) |

**Seq2seq (только important, удвоенные пары):**

| Split | Пар | Шаблонов |
|-------|-----|----------|
| Train | 3146 | 116 |
| Val | 666 | 24 |
| Test | 688 | 24 |

### 2.4 Что изменено в коде

**`nlp-service/train_classifier.py`:**
- `load_dataset()` теперь возвращает `(texts, labels, template_ids)`;
- Добавлена функция `split_by_templates()` — группирует индексы по `template_id`, перемешивает шаблоны, распределяет по сплитам;
- Train/val/test split заменяет старый random split;
- Добавлена оценка на hold-out test set после обучения;
- CLI аргументы: `--val-ratio 0.15 --test-ratio 0.15`.

**`nlp-service/train_seq2seq.py`:**
- `load_pairs()` теперь возвращает `(inputs, targets, template_ids)` — `template_id` привязан к каждой паре (формализация и тезисы наследуют ID исходного примера);
- Добавлена аналогичная `split_by_templates()`;
- Добавлена оценка на hold-out test set;
- CLI аргументы: `--val-ratio 0.15 --test-ratio 0.15`.

### 2.5 Верификация отсутствия data leakage

Проверено программно: пересечение множеств `template_id` между train, val и test пусто для обоих скриптов. Ни один шаблон не присутствует одновременно в двух сплитах.

## 3. Baseline-оценка нетренированных моделей

### 3.1 Цель

Оценить качество базовых (не fine-tuned) моделей на hold-out test set для установления нижней границы (baseline). Эти результаты будут сравниваться с fine-tuned моделями и LLM-подходом (Qwen) для демонстрации эффекта дообучения.

### 3.2 Как воспроизвести

```bash
cd nlp-service

# Полная оценка (classifier + seq2seq на 50 примерах)
python3 eval_baseline.py --limit 50

# Только classifier (быстро, ~5 сек на 447 примеров)
python3 eval_baseline.py --skip-seq2seq

# Все примеры (seq2seq ~25 мин на CPU)
python3 eval_baseline.py
```

Скрипт `eval_baseline.py` автоматически:
1. Загружает `dataset.jsonl` и делает split по `template_id` (70/15/15, seed=42);
2. Берёт test split (447 примеров, 322 important + 125 not-important);
3. Загружает базовые модели из HuggingFace (без fine-tuned весов);
4. Считает метрики: accuracy, F1, precision, recall, confusion matrix (classifier); ROUGE-1/2/L (seq2seq).

### 3.3 Результаты: ImportanceClassifier (base rubert-tiny2)

Модель: `cointegrated/rubert-tiny2` (29 MB, 3 layers, 312 hidden dim).
Классификационная голова (`Linear(312, 2)`) инициализирована случайно — модель не обучена определять важность обращений.

| Метрика | Значение |
|---------|----------|
| Test examples | 447 (322 imp / 125 not-imp) |
| Accuracy | 0.5235 |
| F1-macro | 0.5231 |
| F1-binary (important) | 0.5103 |
| Precision-macro | 0.6753 |
| Recall-macro | 0.6644 |
| Avg latency | 10.1 ms/example |

**Confusion matrix:**

|  | Pred: not-imp | Pred: imp |
|--|---------------|-----------|
| True: not-imp | TN=123 | FP=2 |
| True: imp | FN=211 | TP=111 |

**Интерпретация:** Базовая модель предсказывает большинство обращений как "не важное" (211 из 322 важных пропущены). F1-macro ~0.52 — лишь немного лучше случайного угадывания. Это ожидаемо: классификационная голова не обучена, модель не умеет различать классы.

Модель: `cointegrated/rut5-base-multitask` (222 MB, encoder-decoder T5). Предобучена на задачах суммаризации и перефразирования русского текста — поэтому может давать осмысленный, хоть и нецелевой, выход.
